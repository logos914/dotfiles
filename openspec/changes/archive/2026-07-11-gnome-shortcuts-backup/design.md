# Design: gnome-shortcuts-backup

## Overview

This change adds a GNOME-specific backup/restore flow implemented as new dispatcher scripts (`dot gnome backup` and `dot gnome restore`) plus a guarded installer integration. The implementation follows the repo’s existing command model: executable files under `scripts/<context>/` sourced through `scripts/core/_main.sh`, with no new top-level entrypoint.

Desktop detection is centralized in `platform::is_gnome` inside `scripts/core/platform.sh`, then reused by installer and GNOME scripts. Detection prioritizes `XDG_CURRENT_DESKTOP` (case-insensitive), falls back to `DESKTOP_SESSION`, and explicitly rejects non-GNOME sessions (`pop`, `kde`, `sway`, `xfce`, `i3`, `lxde`, `mate`, `cinnamon`).

Backup format is canonical `dconf dump`. The backup command writes a generated header and concatenated dumps for GNOME keybinding paths into `gnome/shortcuts.dconf`. Restore performs `dconf load` from that file. Backup remains manual-only; installer auto-runs restore only on GNOME and only when backup exists.

Installer changes are additive: existing `gsettings` calls remain and are wrapped with `platform::is_gnome`. After those existing calls, installer conditionally invokes `dot gnome restore`; if `gnome/shortcuts.dconf` is absent, it logs and continues without prompt or failure.

## `platform::is_gnome` detection

Function added in `scripts/core/platform.sh` (available everywhere through `scripts/core/_main.sh`):

```bash
platform::is_gnome() {
  local xdg="${XDG_CURRENT_DESKTOP:-}"
  local session="${DESKTOP_SESSION:-}"
  local normalized

  normalized="$(printf '%s:%s' "$xdg" "$session" | tr '[:upper:]' '[:lower:]')"

  # Explicit non-GNOME rejections first (including Pop!_OS COSMIC "pop")
  if [[ "$normalized" =~ (^|[:;])?(pop|kde|sway|xfce|i3|lxde|mate|cinnamon)($|[:;])? ]]; then
    return 1
  fi

  # Primary detection: XDG_CURRENT_DESKTOP contains gnome (GNOME, ubuntu:GNOME, GNOME-Classic)
  if [[ "${xdg,,}" =~ (^|[:;])gnome([:-]|$) ]]; then
    return 0
  fi

  # Fallback: DESKTOP_SESSION contains gnome
  if [[ "${session,,}" == *gnome* ]]; then
    return 0
  fi

  return 1
}
```

Notes: GNOME-on-Wayland still exposes GNOME in `XDG_CURRENT_DESKTOP`, so primary detection remains valid. If GNOME is detected but `dconf` is missing, detection still returns true; callers enforce binary checks.

## Backup script — `scripts/gnome/backup`

Implementation flow:

1. `#!/usr/bin/env bash`, `set -euo pipefail`, source `"$DOTFILES_PATH/scripts/core/_main.sh"`, `docs::parse "$@"`.
2. Resolve repo root: prefer `DOTFILES_PATH`; fallback `repo_root="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"`.
3. Guard: `platform::is_gnome || { output::error "GNOME is required"; exit 1; }`.
4. Dependencies: require `dconf`; `gsettings` is NOT required for backup.
5. Ensure `"$repo_root/gnome"` exists; stage to `tmp_file="$(mktemp)"` with trap cleanup.
6. Write header line: `# GENERATED by dot gnome backup` (plus timestamp comment).
7. Append exact dumps in order:
   - `dconf dump /org/gnome/desktop/wm/keybindings/`
   - `dconf dump /org/gnome/shell/keybindings/`
   - `dconf dump /org/gnome/settings-daemon/plugins/media-keys/`
8. Move temp file to `"$repo_root/gnome/shortcuts.dconf"` atomically.
9. Log success with `output::answer` and exit 0.

`dconf dump` is chosen over `gsettings list-recursively` (lossy for nested custom-keybinding subpaths) and over custom JSON (non-native format requiring schema mapping and migration logic).

## Restore script — `scripts/gnome/restore`

Implementation flow:

1. `#!/usr/bin/env bash`, `set -euo pipefail`, source `_main.sh`, parse docs.
2. Resolve `repo_root` same as backup; set `backup_file="$repo_root/gnome/shortcuts.dconf"`.
3. Guard GNOME via `platform::is_gnome`; fail cleanly if false.
4. Require `dconf` binary; `gsettings` not required.
5. If file missing: `output::error "Backup file not found: gnome/shortcuts.dconf"; exit 1`.
6. If file exists but empty/whitespace: `output::answer "Backup file is empty, nothing to restore"; exit 0`.
7. Restore command:
   - `dconf load /org/gnome/ < "$backup_file"`
8. Log completion and exit 0.

`dconf load` is idempotent for same input: re-running converges to the same values and does not mutate backup content.

## Installer integration

In `scripts/self/utils/install.sh`, inside `install_linux_custom`, wrap the existing GNOME `gsettings set ...` block with:

1. `if platform::is_gnome; then`
2. Run current GNOME keybinding/custom-keybinding `gsettings` calls unchanged (just indented into guarded block).
3. After those calls, check `"$DOTFILES_PATH/gnome/shortcuts.dconf"`:
   - exists → `"$DOTFILES_PATH/bin/dot" gnome restore | log::file "Restoring GNOME shortcuts"`
   - missing → `output::answer "no backup found, skipping restore"`
4. `else` branch logs skip for non-GNOME and continues.

Exit semantics: guard GNOME-only commands behind detection; backup-missing is non-fatal; restore errors (existing but invalid file) should bubble up.

## Edge cases & landmines

- `XDG_CURRENT_DESKTOP` unset: fallback to `DESKTOP_SESSION`; otherwise treat as non-GNOME.
- GNOME Wayland sessions: still detected through `XDG_CURRENT_DESKTOP=GNOME` (or variants like `ubuntu:GNOME`).
- Snap/Flatpak sandbox: `dconf` bus access may fail; script exits non-zero with dependency/runtime error (no silent success).
- `gnome/shortcuts.dconf` empty: manual `dot gnome restore` exits 0 with “nothing to restore”; installer skips silently by existence+size check.
- `gsettings` missing on GNOME-like env (e.g., WSL): installer’s GNOME block should check `platform::command_exists gsettings`; otherwise log and skip keybinding writes.
- Running install as root: dconf applies to root’s profile, not target user; document that `dot self install` should run as intended desktop user.
- `dot self` remains destructive/update-related; no new automation may trigger `dot self install` from backup/restore or other scripts.
